# Internals: Speakers Page

Technical reference for how the `/speakers/` page works. Intended for developers maintaining or extending the feature.

---

## Files Involved

| File | Purpose |
|---|---|
| `layouts/_default/speakers.html` | Main list layout — overrides the theme's speakers.html |
| `content/speakers/*.md` | One file per speaker — source of all speaker data |
| `content/speakers/_index.md` | Section index; sets the layout to `speakers` |
| `themes/codeCamp/assets/css/main.css` | All speaker card and overlay CSS (search for `/* ── Speaker`) |

---

## How the Speaker List Is Built

The template starts by loading all regular pages in the speakers section and filtering to the current year:

```gotemplate
{{ $speakers := where .RegularPages "PublishDate.Year" (now.Year) }}
{{ $sorted   := sort $speakers "Params.weight" "asc" }}
```

`PublishDate` is derived from the `date` field in each speaker's frontmatter. If a speaker's `date` is set to a past year, they will be filtered out and will not appear on the page. This is by design — it allows the same template to always show only the current year's speakers without any manual toggling.

---

## How Cards Are Generated

Cards are not generated by a component or shortcode — they are rendered inline by the template using a `range` loop. The template separates speakers into two groups:

1. **Keynote speakers** — `where $sorted "Params.keynote" true`
2. **Regular speakers** — `where $sorted "Params.keynote" "ne" true`

Keynote speakers render first in a separate section with gold styling. Regular speakers render below in the main grid.

Each card is a `<div>` with:
- `role="button"` and `tabindex="0"` for keyboard accessibility
- `data-bio="bio-{id}"` — points to a hidden `<template>` element containing the bio content
- CSS classes: `speaker-card` (all cards) + `speaker-keynote-card` (keynote only)

---

## The Hidden Template Pattern

Before the visible cards, the template renders one `<template>` element per speaker:

```html
<template id="bio-bphogan">
  <h2>Brian P. Hogan</h2>
  [rendered bio HTML]
</template>
```

`<template>` elements are inert — browsers parse but do not render or execute their contents. When a card is clicked, JavaScript clones the matching template's content into the overlay panel. This approach avoids re-fetching data or parsing HTML on click, and sidesteps issues with escaping arbitrary HTML in data attributes.

The ID is derived from the speaker's URL slug:
```gotemplate
{{ $id := .RelPermalink | strings.TrimRight "/" | path.Base }}
```
For example, `/speakers/bphogan/` → `bphogan` → `id="bio-bphogan"`.

## The Overlay Mechanism

The overlay is a fullscreen fixed `<div id="speaker-overlay">` that lives at the bottom of the page markup. It is hidden by default and made visible by adding the `.open` class.

**Opening flow:**
1. User clicks a `.speaker-card`
2. JS reads `card.dataset.bio` to find the matching `<template>` ID
3. Template content is cloned (`tmpl.content.cloneNode(true)`) and injected into `#speaker-bio-content`
4. `.open` class added to overlay → CSS transition fades in backdrop, flips in panel
5. Focus moves to the close button (accessibility)

**Closing flow:**
- Close button click
- Click outside the panel
- Escape key

On close, the content is cleared after a 500ms delay (matching the CSS transition duration) so the flip-out animation completes before the DOM is emptied.

**Focus management:** The last focused card is stored in `lastFocused`. When the overlay closes, focus returns to that card — required for keyboard and screen reader accessibility.

## Photo Logic

Photo rendering is extracted into a shared partial at `layouts/partials/speaker-photo.html`, called in both the keynote and regular card sections:

```gotemplate
<div class="speaker-card-photo-wrap">
  {{ partial "speaker-photo.html" . }}
</div>
```

The partial receives the speaker page object as its context (`.`) and checks for photos in this order:

1. `images` array with 2+ entries → renders a stacked multi-photo layout
2. `images` array with 1 entry → falls through to `image` check (single photo)
3. `image` field set → renders a single circular photo
4. Neither set → renders the faded CVCC logo placeholder

The same partial is also called from `layouts/_default/sessions.html` when rendering speaker photos inside session overlays — see the "Speaker Photos in the Overlay" section of `docs/deepdive-sessions-page.md`.

**Single photo:**
```html
<img src="/img/speakers/photo.jpg" class="speaker-card-photo">
```
CSS: `width: 110px; height: 110px; border-radius: 50%; object-fit: cover; object-position: top center`

The `object-position: top center` ensures face cropping — the top of the image is prioritized when the circle clips the photo.

**Multi-photo stack:**
```html
<div class="speaker-card-photo-stack">
  <img class="speaker-card-photo-stacked">  <!-- first: no offset -->
  <img class="speaker-card-photo-stacked">  <!-- second: margin-left: -24px -->
</div>
```
Each stacked photo is 80px. Subsequent photos use `margin-left: -24px` to overlap. A white border (`border: 3px solid #fff`) separates them visually. A `box-shadow` on the second photo adds depth.

**Fallback for broken stacked images:**
JavaScript listens for `error` events on `.speaker-card-photo-stacked` elements. If an image fails to load, the src is replaced with the CVCC placeholder and `.speaker-card-photo-stacked--fallback` is added (applies `opacity: 0.2` and `object-fit: contain`).

**Photo wrap fixed height:**
`.speaker-card-photo-wrap` has `height: 110px; display: flex; align-items: center; justify-content: center`. This ensures the speaker name always aligns at the same vertical position across all cards, regardless of whether the card has a single photo (110px), a stacked group (80px), or a placeholder.

## Card Grid Layout

Both the keynote grid and the regular speaker grid use a flexbox approach:

```css
display: flex;
flex-wrap: wrap;
justify-content: center;
gap: 1.5rem;
```

Each `.speaker-card` has `flex: 0 0 calc(25% - 1.125rem)` — this is exactly one column in a 4-column row with 3 gaps of 1.5rem:

```
4 × card_width + 3 × 1.5rem = 100%
card_width = (100% - 4.5rem) / 4 = 25% - 1.125rem
```

`justify-content: center` means partial rows (e.g., 1 or 3 keynote speakers) are centered rather than left-aligned.

**Mobile breakpoint (`max-width: 600px`):**
```css
.speaker-card { flex: 0 0 calc(50% - 0.5rem); }
```
Collapses to a 2-column grid. `2 × card_width + 1 × 1rem = 100%` → `card_width = 50% - 0.5rem`.

## Keynote Card CSS

`.speaker-keynote-card` adds a gold treatment on top of the base `.speaker-card` styles:

```css
border: 3px solid #f0c020;
box-shadow: 0 0 0 4px rgba(240, 192, 32, 0.18), [elevation shadow];
```

The keynote section label (`✦ Keynote Speaker`) uses:
```css
font-size: 0.75rem;
text-transform: uppercase;
letter-spacing: 0.12em;
color: #b8860b;
```

The label text automatically pluralizes: `"✦ Keynote Speaker{{ if gt (len $keynote) 1 }}s{{ end }}"`.

## Company Logo Toggle

The `$showCompanyLogos` variable is read at the top of the template:

```gotemplate
{{ $showCompanyLogos := false }}
{{ with site.Data.conference }}{{ $showCompanyLogos = .showCompanyLogos }}{{ end }}
```

It defaults to `false` if `data/conference.yaml` doesn't exist. If the file exists and contains `showCompanyLogos: true`, company logos are enabled.

When `showCompanyLogos` is `true`:
- Speaker has `companyLogo` → renders `<img class="speaker-card-company-logo">`
- Speaker has no `companyLogo` → renders the faded CVCC badge (`speaker-card-logo`)

When `showCompanyLogos` is `false` → nothing renders in the logo slot.

## Overlay Flip Animation

The panel uses a CSS 3D perspective flip:

```css
.speaker-bio-panel {
  transform: perspective(1200px) rotateY(-90deg);
  transition: transform 0.5s cubic-bezier(0.34, 1.2, 0.64, 1);
}

#speaker-overlay.open .speaker-bio-panel {
  transform: perspective(1200px) rotateY(0deg);
}
```

`rotateY(-90deg)` positions the panel edge-on (invisible). Adding `.open` rotates it to face forward. The cubic-bezier `(0.34, 1.2, 0.64, 1)` gives a slight overshoot (spring feel) at the end of the animation.

The backdrop fade is handled separately:
```css
#speaker-overlay { background: rgba(0, 0, 0, 0); transition: background 0.3s ease; }
#speaker-overlay.open { background: rgba(0, 0, 0, 0.55); }
```

## Accessibility

- Cards use `role="button"` and `tabindex="0"` (they are `<div>` elements, not native buttons)
- `aria-label="Read bio for {name}"` provides a meaningful label for screen readers
- Keyboard: `Enter` and `Space` open the overlay; `Escape` closes it
- Focus is trapped to the close button on open and returned to the triggering card on close
- `aria-modal="true"` on the overlay signals to screen readers that it is a modal dialog
